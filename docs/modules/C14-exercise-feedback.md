# C14 — exercise-feedback

**Tier:** Client
**Code location:** `apps/mobile/lib/features/learn/feedback/`
**Milestone:** 3
**Status:** not started

## Purpose

The shared exercise interface and the feedback surface behind it. It defines the
contract all four exercise types implement, and it owns what happens the instant
an answer lands: immediate confirmation or the pre-generated explanation, the
correct answer, and the route to the tutor. The "no hard fail" promise is
delivered here and in `E01`.

## Scope

**Owns**
- The exercise contract every type implements
- The feedback surface: correct confirmation, incorrect explanation, correct
  answer display
- The "still confused? ask the tutor" affordance and its context handoff
- Dispatching the reward beat to `E04`
- Reporting the result to `E01`

**Does not own**
- The re-queue decision → `E01`
- Reward choreography itself → `E04`
- Explanation text → pre-generated by `B05`
- The tutor → `C18`, `B16`

## Interface

The exercise contract: receive a payload, emit an answer, render a result state.
Deliberately narrow — an exercise type cannot decide correctness, cannot award XP,
and cannot navigate. That keeps four independent modules interchangeable and
individually testable.

## Decisions inherited

- **Immediate feedback**: correct gets a satisfying confirmation plus an XP tick;
  wrong gets the pre-generated explanation of *why*, plus the correct answer, plus
  a route to the tutor (`FEATURE_PLAN.md:97`).
- **No hard fail.** A wrong answer does not block progress; the missed exercise is
  re-queued at the end of the lesson (`FEATURE_PLAN.md:98`). This module renders
  that as a second chance, never as a penalty.
- **Explanations are pre-generated with the lesson**, which is what makes this
  surface zero-latency (`FEATURE_PLAN.md:79`).
- **Every answer result is logged** with exercise id, correctness, and latency
  (`FEATURE_PLAN.md:99`).

## Feel spec

The asymmetry between correct and incorrect is the point:

- **Correct** — brief, celebratory, and *out of the way*. Confirmation, XP tick,
  auto-advance. The user should barely stop moving.
- **Incorrect** — calm, unhurried, and explanatory. No auto-advance, no red
  screen, no error haptic. The explanation is the hero of the frame and the
  correct answer sits next to it. The tutor affordance is present but not
  shouting.

Nothing about a wrong answer should feel like a loss, because mechanically it is
not one.

## Latency budget

Answer to feedback within one frame per `E06`. The explanation is already in
memory; there is no acceptable reason for this surface to wait.

## Degradation

Fully offline. If an explanation is somehow missing from the payload, show the
correct answer plus the tutor affordance rather than an empty state.

## Accessibility

Correct and incorrect are announced explicitly, not implied by colour or motion.
The explanation is read in full by screen readers. The tutor affordance is
labelled with what it does, not just an icon.

## Open questions

- Whether the tutor affordance pre-fills "why is my answer wrong?" or opens an
  empty thread. Pre-filling matches the quick actions in `FEATURE_PLAN.md:80` and
  is one tap cheaper.
- Whether a re-queued exercise's feedback differs on the second pass — showing the
  same explanation again may be redundant.
- **Whether to add a "report this card" affordance.** v1 ships AI content with no
  human review gate, and `P17`'s automated gate is the only check — so there is
  currently no path for a learner who spots something wrong. The source covers
  reporting only for v2 community content (`FEATURE_PLAN.md:210`). This surface is
  where a report would naturally live, it is cheap, and it would give `P14`'s
  citation trail somewhere to be useful. Flagged as a product decision, not
  assumed. See `P17`.

## Acceptance criteria

- [ ] All four exercise types implement the contract without correctness logic
- [ ] Feedback renders within one frame, offline included
- [ ] Correct auto-advances; incorrect waits for the user
- [ ] No error haptic, red screen, or loss language appears anywhere
- [ ] The tutor opens with the current exercise and the user's answer as context
- [ ] Every result reaches `E01` with correctness and latency
